Conditional Access policy templates - Secure foundation (SF)

Conditional Access templates จาก Conditional Access policy templates ช่วยให้เราสามารถสร้าง policy ตามคำแนะนำจาก Microsoft ได้โดยง่าย

Templates มีหลายหมวด ในคู่มือนี้จะทำหมวด Secure foundation ที่เป็น Conditional Access พื้นฐานที่ทุกองค์กรควรทำนะครับ

Prerequisites

Review enabled authentication methods

Conditional Access สามารถใช้งานร่วมกับ MFA ได้หลายแบบ เราอาจจะตรวจสอบก่อนว่า tenant ได้เปิดใช้งาน MFA ทุกแบบตามต้องการแล้วหรือยัง?

Create a pilot user group

Conditional Access policy ที่ apply เข้าหา All users อาจสงผลกระทบต่อการใช้งานโดยไม่คาดคิด

ในช่วงเริ่มต้น เราควร apply เขาเข้าหา pilot user group เพื่อทดสอบการใช้งานก่อน

SF01 - Require multifactor authentication for admins

Account ที่มีสิทธิ์บริหารจัดการระบบมักเป็นเป้าโจมตีของผู้บุกรุก

Account เหล่านี้ควรถููกบังคับใช้ MFA เพื่อลดความเสี่ยงจากการถูกโจมตีในอนาคต

Create and turn on the policy

1. สร้าง policy จาก template

ปรับชื่อ และ รีวิวค่า settings

ปรับชื่อ เช่น เติม suffix "Seceure foundation" หรือ SFnn ที่ด้านหน้า policy

สังเกตว่า policy จะ apply เข้าหา adminitrative account เท่านั้น

แล้วกด Create

กด policy เข้าไปแก้ไขเพิ่มเติม

2. ปรับ policy

ควร exclude emergency access หรือ break-glass account จาก Manage emergency access accounts in Microsoft Entra ID

รวมถึง servie account ถ้าจำเป็น เช่น service account ที่ไม่รองรับ MFA แต่อยู่ใน administrative group ใด group นึง

เปิดใช้งาน policy แล้ว Save

ตอนนี้เราได้ Conditional Access policy สำหรับ Secure foundtaion ตัวแรกแล้วนะครับ

Policy นี้ต้องการให้ผู้ใช้ต้องทำ MFA ก่อนเข้าไป register ข้อมูลอะไรก็ตามใน Security Info ของเขาเอง

1. สร้าง policy จาก template

ปรับชื่อ และ รีวิวค่า settings

เข้าไปปรับค่า setting ต่อ

2. เพิ่ม break-glass account เข้าไปใน exclusion

3. เปิดใช้งาน policy

Test

1. ถ้าเราพยายามเข้า security info เราจะถูก request MFA

ปรับชื่อ และ รีวิวค่า settings

2. แต่ถ้าเราไม่ต้องการให้มี MFA ถ้า request มาจาก network ภายในของบริษัท

ให้เราสร้าง location เช่น HQ

ระบุ public IP ที่ client ใน HQ network ใช้ access Internet

แล้ว mark เป็น trusted network

3. เมื่อลองเข้า Security Info จะ network ภายใน HQ อีกครั้ง

ก็จะไม่มี MFA prompt ครับ

SF03 - Block legacy authentication

Microsoft แนะนำให้เรา block authentication ที่ใช้ protocol เก่าๆ ที่ไม่รองรับ MFA เช่น basic authentication

Identify legacy authentication use

ดังนั้น ให้เราตรวจสอบจาก Sign-in log ก่อนว่า ในบริษัทเรามี authentication จาก app ใด ที่ใช้ legacy authentication อยู่บ้าง

ถ้าพบ ก็ลองพิจารณาดูว่าจะทำอย่างไรนะครับ

เช่น ในภาพนี้ พบ SMTP Auth จาก service account ชื่อว่า app1 ที่ยังใช้ basic authentication relay mail มาที่ Exchange Online อยู่

Create and turn on the policy

1. สร้าง policy จาก template

ปรับชื่อ และ รีวิวค่า settings

แล้วเข้าไปใน policy ต่อ

2. เพิ่ม break-glass account ใน exclusion

3. เปิดการใช้งาน policy และ Save

Test impacts

1. ลองส่่ง mail จาก app1 เข้าหา user ในองค์กร

โดยใช้ basic authentication

$Username = "app1@cloud.coms.ws"
$Password = "Jxxxxxxxx"
$SecurePassword = ConvertTo-SecureString -String $Password -AsPlainText -Force
$Creds = New-Object System.Management.Automation.PSCredential ($Username, $SecurePassword)

Send-MailMessage -From "app1@cloud.coms.ws" `
                 -To "user1@cloud.coms.ws" `
                 -Subject "Test Email via Basic Authentication" `
                 -Body "This is a test email." `
                 -SmtpServer "smtp.office365.com" `
                 -UseSsl `
                 -Credential $Creds `
                 -Port 587

ตอนนี้ส่งไม่ได้แล้วนะครับ

2. แต่ช่วงนี้เรายังไม่ได้เปลี่ยนไปใช้ OAuth จึงขอ exclude app1 service account ไม่ให้ถูก policy นี้ apply เข้าหาขั่วคราว

ตอนนี้ app1 ใช้ basic authentication ส่ง mail ได้แล้วนะครับ

หมายเหตุ: ถึงแม้ว่า SMTP AUTH ยังใช้ basic authentication ได้อยู่ แต่ กันยายน 2568 ก็จะใช้ไม่ได้แล้วนะครับ จาก Deprecation of Basic authentication in Exchange Online

ดังนั้น เราต้องวางแผนย้ายไปใช้ authentication protocol ตัวอื่นในการส่ง mail แทน เช่น OAuth เป็นค้นครับ
